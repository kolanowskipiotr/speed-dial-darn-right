# Patterns & Conventions

## CRUD pattern
All data mutations follow this exact sequence:
```
mutate data → saveData() → render()
```
`saveData()` automatically triggers a debounced background sync to Google Drive via the `uploader` sidecar.

## Adding a new feature — checklist
1. **Data** — add field to dial/group/tab object in the relevant CRUD function; load it in the corresponding `open*Modal()`
2. **Render** — update `makeDialCard()` (`domain/dial/render-dials.js`) or the relevant `render*` function for your domain
3. **HTML** — add UI to the relevant domain partial (`domain/<domain>/modal-*.html`)
4. **CSS** — add styles in the relevant domain CSS file (`domain/<domain>/styles.css`); use existing CSS vars, never hardcode colours
5. **Script order** — if adding a new JS file, insert the `<script>` tag in `index.html` in dependency order (helpers before render before crud), before `domain/ui/init.js`
6. No build step — changes to mounted files are live immediately in the Docker dev setup

## Domain file structure
Each domain follows this split pattern:
- `helpers.js` — module-level state vars and shared utility functions
- `render.js` — pure render functions (DOM builder)
- `crud.js` — data mutation + UI open/close handlers
- `editor.js` / `drag.js` — specialised sub-concerns (todo, notes)

Global scope is shared across all non-module scripts. State vars must be declared in the first file loaded for their domain (`helpers.js`).

## IDs
- Generated by `uid()` in `domain/core/utils.js`: `Date.now().toString(36) + random`, always `[a-z0-9]+`

## Undo
- `showToastUndo(msg, backup)` — take `backup = JSON.stringify(data)` **before** the mutation

## Favicon loading
- `attachFavicon()` in `domain/core/utils.js` tries ordered candidates via `img.onerror` chain, falls back to emoji

## Page title auto-fetch
- `fetchPageTitle()` fires on URL field blur — `fetch()` + regex on raw HTML

## Weather domain

`domain/weather/weather.js` is a self-contained domain. Key globals: `toggleWeatherPopup()` (called from `header.html`), `_closeWeatherPopup()` (called from `init.js` Escape handler), `initWeather()` (called from `init.js`). Config persisted to `localStorage` key `speedDial_weather`. Weather fetched from Open-Meteo (free, no API key). WMO code tables are defined in the module — these are weather data constants, not UI icons.

## Page Monitor domain

`domain/monitor/` — background page-change watcher. Key globals: `initMonitor()`, `toggleMonitorPopover(e)`, `_closeMonitorPopover()`, `openMonitorManageModal()`, `openMonitorPageModal(id?)`, `saveMonitorPage()`, `monitorAcknowledge(id)`, `monitorCheckNow(id)`, `deleteMonitorPage(id)`.

- Checking is **server-side** via the uploader sidecar (`POST /api/monitor/check`, no auth) to avoid browser CORS restrictions.
  - **Plain fetch** (default): strips HTML and returns a SHA-256 of visible text. Fast, suitable for server-rendered pages.
  - **Headless browser** (`useHeadless: true`): launches system Chromium via `puppeteer-core`, waits for `networkidle2`, extracts `document.body.innerText`. Required for JS-rendered SPAs (React, Vue, Angular, …). The uploader `Dockerfile` installs the `chromium` Alpine package and sets `PUPPETEER_EXECUTABLE_PATH`.
- Per-page `setInterval` timers live in `_monitorTimers` (Map). Timers are rebuilt by `_rescheduleAllMonitors()` on init, and updated individually on add/edit.
- The header indicator (`#monitorIndicator`) uses the same `.gdrive-indicator` + `.connected`/`.conflict` class pattern as the other status dots.
- The popover (`#monitorPopover`) is inside `.monitor-indicator-wrap` (position: relative). It closes on outside click (wired in `init.js`).
- In **edit mode**, clicking the indicator opens the manage modal instead of the popover.

## Icons & emoji — single source of truth

All UI icons/emojis are defined in `domain/core/state.js` (loaded first). Never hardcode emoji strings outside of data definitions:

```js
// ✅ correct
showToast(`${ICONS.warn} Please enter a name`);
button.textContent = ICONS.edit;

// ❌ wrong
showToast('⚠️ Please enter a name');
button.textContent = '✏️';
```

`ICONS` keys: `defaultDial`, `defaultGroup`, `defaultTab`, `faviconFallback`, `edit`, `delete`, `search`, `ok`, `warn`, `error`, `undo`, `loading`, `defaultTodoList`, `check`, `uncheck`, `moveTop`, `moveBottom`.

Emoji data (all in `domain/core/state.js`): `ICONS`, `EMOJI_CATEGORIES`, `EMOJI_LIST`, `GROUP_EMOJIS`, `EMOJI_KEYWORDS`.
Synonym search data: `EMOJI_SYNONYMS` in `domain/ui/emoji-synonyms.js`.

## Emoji picker
- Built once in `initEmojiPickers()`, reused across all modals
- Search checks `EMOJI_SYNONYMS[e]` first (synonym array), then `EMOJI_KEYWORDS[e]` (primary keyword string)

## Themes
- Applied via `data-theme` attribute on `body`
- All theme colours are CSS vars on `body` — never hardcode
- Theme definitions and application logic live in `domain/core/themes.js`

## Modals
- `openModal(id)` / `closeModal(id)` toggle the `.open` class on the backdrop
- All modals share a `.modal-backdrop` and `.modal` structure (styles in `domain/ui/modals.css`)
- Escape key closes all open modals (wired in `domain/ui/init.js`)

## CSS variables (never hardcode)
```css
--bg, --surface, --surface2, --surface3   /* backgrounds */
--border, --border-hover                  /* borders */
--accent, --accent2, --accent-text        /* brand colors */
--text, --text-dim, --text-dimmer         /* typography */
--danger, --success                       /* status */
--radius (14px), --radius-sm (8px)
--transition (0.2s cubic-bezier)
```
